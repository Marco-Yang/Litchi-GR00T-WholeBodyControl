## 0. 先用一句话理解

机器人做长任务时，底层已经有一套「技能控制器」（VLA）负责走路、抓玩偶、拎篮子。  
以前靠**人按键盘**告诉它「这个技能做完了，换下一个」。  

我们训练的 agent，就是要**学会看画面 + 机器人关节状态，判断「当前技能做完了没有」**，做完了就自动发和下人手动按 `2` / `3` 一样的切换命令。

所以：

| 角色 | 干什么 | 类比 |
|------|--------|------|
| VLA（共享视觉语言模型 + 三个动作头） | 真正控制机器人动作 | 工人 |
| Skill Agent（本文） | 判断技能是否完成、何时换下一个 | 工长 / 裁判 |
| 人（示范时） | 按键切换，留下「正确答案」 | 老师 |

Agent **不会**自己学走路或抓东西；它只学「什么时候该换技能」。

## A. 基本原理：这类 agent 到底在学什么

这一节不讲命令、不讲文件，只讲**思想**。搞懂这一节，后面所有细节都是「把这套思想工程化」。

### A.1 先分清：不是强化学习里的「自己试错」

很多人听到「训练 agent」会想到强化学习（RL）：机器人自己乱动，成功了给奖励，失败了扣分。

**本项目不是那样。**

我们用的是**有监督模仿学习（supervised learning / behavior cloning 的一种）**：

1. 人已经示范过「什么时候该切技能」；  
2. 把示范切成大量带对错的样本；  
3. 模型反复看这些样本，把预测往正确答案上靠；  
4. 上真机时，用学到的判断代替人手按键。

类比：不是让裁判自己下场踢球找感觉，而是给裁判看很多场「老师已经吹过哨」的录像，让他学会「该吹哨的画面长什么样」。

| 常见说法 | 本项目实际做的事 |
|----------|------------------|
| 强化学习 agent | ❌ 没有奖励函数、没有自己试切技能 |
| 端到端控制策略 | ❌ 不输出关节动作 |
| 技能完成检测器 / 调度器 | ✅ 输出「完成概率」，再叠加规则切技能 |
| 从示范里学切换时机 | ✅ 老师 = 人的按键（可再手工微调时间） |

### A.2 核心问题可以写成一句话

对任意时刻 \(t\)，给定：

- 当前正在执行的技能 \(s\)（1 / 2 / 3）；  
- 最近几秒的相机画面；  
- 与画面对齐的机器人本体状态；  

估计：

\[
P(\text{当前技能已完成} \mid \text{画面}, \text{本体}, s)
\]

若这个概率持续够高，并且过了「跑够最短时间 / 关节门禁」等规则，就发出切换命令。

**模型只负责概率；规则负责别乱切。** 这是刻意设计：小数据下，纯神经网络容易偶发抖动，规则兜底更安全。

### A.3 为什么用「大视觉语言模型」而不是手写 if-else

手写规则举例：

- skill1：画面里桌子够大、腿速接近 0 → 完成；  
- skill2：右臂角度回到某范围 → 完成；  
- …

手写的问题：

- 桌面布置、玩偶位置、光照一变就碎；  
- skill1「走到桌前」很难用单一关节阈值表达；  
- 完成往往是「画面 + 姿态」的组合，规则会越写越长。

视觉语言模型（VLM）的好处：

- 预训练时已经见过海量图文，懂「桌子 / 玩偶 / 篮子 / 手臂」等概念；  
- 我们用中文把「完成标准」写进提示词，等于给模型一份考卷说明；  
- 再用**少量示范**微调，把它从「通用聊天」拧成「专门判这个任务完没完」。

代价是：需要 GPU、需要示范、需要小心别让它只抄图像捷径（所以才有本体 + image dropout）。

### A.4 学习信号从哪来？（老师是谁）

老师不是另一段程序，而是**人在示范里按切换键的时刻**。

但人按键通常略晚于「客观完成」：

```text
客观完成 ──(反应时间)──► 人手按 2/3
```

所以训练时不会只拿「按键那一帧」当唯一正样本，而是：

- 按键前一小段 → 标成「已完成」；  
- 再往前一段模糊区 → 丢掉不训；  
- 更早 → 标成「未完成」。

这叫**从事件时间戳导出逐帧标签**。网页里还能把按键时间往前挪，让「老师」更接近真实完成瞬间。

### A.5 一次前向里发生了什么（原理级）

可以把 Qwen3-VL 想成一条流水线：

```text
图像 ──► 视觉编码器 ──► 一串「图像词」 ─┐
文字提示 ──► 分词/嵌入 ──► 一串「文字词」─┼──► 语言模型（Transformer）──► 下一个词的分数
本体数字 ──► 小 MLP ──► 伪装成的「本体词」─┘
```

训练时我们让「下一个该出现的词」尽量是正确的 ` true` 或 ` false`。  
推理时不生成整句 JSON，只比较这两个词的分数，得到 \(P(\text{done})\)。

**为什么可以这么干？**  
因为底座模型本来就会「续写」；我们把它的续写能力窄化成二选一：在固定前缀 `{"done":` 后面，只能续 ` true` 或 ` false`。  
这比让模型自由生成整段 JSON 更稳、更快、也更好算概率。

### A.6 LoRA：为什么不全量重训 40 亿参数

全量微调：改动整本「百科全书」——贵、容易把通用能力冲掉、权重文件巨大。  

LoRA：在关键层旁边加很小的「补丁矩阵」。训练只更新补丁；部署时加载补丁即可。  

对本项目：

- 视觉塔冻住（别把基础看图能力训坏）；  
- 语言模型挂 LoRA（学会「按我们的完成标准判断」）；  
- 另训一个很小的本体编码器（底座原本不会直接吃 154 维关节向量）。

### A.7 多模态为什么容易「偷懒」，以及我们怎么逼它老实

神经网络会优先用**最容易降低损失**的信号。  
若图像已经足够猜对「完没完」，它会**无视本体**——训练曲线很好看，真机一换场景或丢状态流就脆。

对策（训练时故意捣乱）：

| 手段 | 在干什么 | 想达到的效果 |
|------|----------|--------------|
| Image dropout | 有时把图换成灰图 | 逼模型从关节判断 skill2/3 完成 |
| Proprio dropout | 有时藏掉本体 | 丢 `g1_debug` 时仍能靠图像撑一阵 |
| 数据增强 | 颜色/裁剪/时间微抖 | 别死记某一帧像素 |

验证时再做「灰图 + 真本体」评估：若这时还分得好，说明本体通路真的学到了，不是虚的。

### A.8 训练好的东西，上真机为什么还要规则

即使 \(P(\text{done})\) 学得不错，单帧分数仍会抖。真机额外要求：

1. **阈值**：例如 ≥ 0.6；  
2. **连续确认**：例如连续 3 次（2 Hz 下约 1.5 s）；  
3. **最短停留**：刚切进来别立刻再切；  
4. **关节门禁**：例如 skill2 右臂必须大致归位，skill3 必须转够角度。

可以把模型看成「建议切」，规则看成「批准切」。  
**小数据机器人系统里，这种「学习 + 规则」比纯端到端更可控。**

### A.9 和「训练 VLA」的本质区别（避免概念混淆）

| | VLA 技能策略 | 本文 Skill Agent |
|--|--------------|------------------|
| 输出 | 动作 / action token | 完成概率 \(P(\text{done})\) |
| 学习目标 | 模仿人的动作轨迹 | 模仿人的切换时机 |
| 频率 | 控制环高频 | 约 2 Hz 决策 |
| 失败形态 | 动作歪、抓空 | 早切、晚切、漏切 |
| 本仓库位置 | GR00T / gear_sonic 部署链 | `agents/skill_agent/` |

两者是上下级：VLA 执行，Agent 调度。

### A.10 一张总图：原理闭环

```text
┌─────────────── 离线学习 ───────────────┐
│ 人示范按键 → 导出 (画面,本体,技能)→标签 │
│ 模型预测 P(done) → 与标签比 → 更新 LoRA │
│            + 本体编码器                  │
└───────────────────┬─────────────────────┘
                    ↓ 得到 adapter
┌─────────────── 在线使用 ───────────────┐
│ 实时画面+本体 → P(done)                  │
│ → 阈值/连击/最短时间/关节门禁             │
│ → 通过则发 skill:N（等同键盘）            │
└─────────────────────────────────────────┘
```

后面章节把这个闭环拆成工程细节。

## 1. 任务长什么样

整段任务固定拆成三个顺序技能：

| 技能 | 名字 | 人眼完成标准（也写进模型提示词） |
|------|------|----------------------------------|
| skill1 | 走到绿桌 | 已在绿桌前停稳，篮和黄玩偶就在身前 |
| skill2 | 抓玩偶放篮 | 玩偶已在篮里，右手已自然下垂归位 |
| skill3 | 拎篮后退右转 | 左手拎着篮，已后退并顺时针右转后停稳 |

示范录制时，人在合适时刻按 `2`、`3`（以及结束）。这些按键时刻就是训练用的「老师标注」。

提示词里会明确告诉模型：当前是哪个 skill、完成标准是什么、完成后应切到哪。  
模型**不需要自己规划任务顺序**——顺序是写死的；它只回答「当前这一段做完没有」。

## 2. 从示范到上真机：整条流水线

```text
① 真机录制示范
     ↓  agents/video/session_*/
② （可选）网页里改切换时间戳
     ↓  agents/annotations/
③ 切帧 + 打标签 + 对齐本体
     ↓  agents/dataset/
④ LoRA 微调 Qwen3-VL-4B（+ 本体编码器）
     ↓  agents/checkpoints/.../adapter/
⑤ 离线回放：对比「人按键」vs「模型想切」
     ↓  .../eval/
⑥ 真机 agent_node：2 Hz 打分，条件满足就发 skill:N
```

每一步的直觉：

1. **录制**：相机视频 + 每帧机器人状态 + 按键事件。  
2. **改标注**：人手慢半拍时，把「真正完成」的时刻往前挪一点。  
3. **建数据集**：把连续视频变成「一张张带对错的考题」。  
4. **训练**：让模型多做对「做完了 / 没做完」这道判断题。  
5. **评估**：用没参与训练的录像检查会不会早切、晚切、漏切。  
6. **部署**：装进和键盘同一个通信口，替代人工按键。

## 3. 示范数据里到底有什么

每个 `agents/video/session_YYYYMMDD_HHMMSS/` 大致包含：

| 文件 | 含义 |
|------|------|
| `cameras.mp4` | 左右拼在一起的双相机画面（胸前 ego + 头部 head） |
| `robot_state.npz` | 与视频帧对齐的本体状态（关节角、手、角速度、motion token…） |
| `skill_events.json` | 开始 / 切技能 / 结束等事件（含时间与帧号） |

**对齐是关键**：录制时状态行与视频帧共用 `frame_index`。  
训练和真机推理都必须保证：某一时刻的图，配的是**同一时刻附近**的关节数据，而不是随便塞一包数。

真机运行时没有录像文件，agent 会：

- 约 10 Hz 缓存相机帧；  
- 同步收 `g1_debug` 本体流；  
- 对选中的相机帧，取**接收时间最近**的一帧状态。

这和离线建数据集时「按帧索引对齐」是同一思想，只是实现从「文件」换成了「实时缓冲」。

建数据集后（`agents/dataset/`）会多出：

| 产物 | 作用 |
|------|------|
| `frames/<session>_ego_view.npy` 等 | 已缩放到模型输入尺寸的 RGB，可 mmap 读取 |
| `frames/<session>_proprio.npy` | 每帧本体基底向量 |
| `frames/<session>_yaw.npy` | 每帧偏航角（再减 skill 起点得到相对转角） |
| `samples.jsonl` | 每行一道题：session、帧、技能、标签、历史帧索引… |
| `meta.json` | 提示配置、标签配置、本体字段、门禁参考统计 |

## 4. 模型在解什么题？（不是聊天，是二分类）

表面上提示词让模型输出 JSON，例如：

```json
{"done": true, "skill": "2", "next": "3"}
```

真正训练和推理时，我们**不让它自由写长文**，而是：

1. 把提示写到 `{"done":` 为止；  
2. 只看下一个词是 ` true` 还是 ` false` 的概率；  
3. 用这两个概率算出一个分数：

\[
P(\text{done}) = \frac{e^{z_{\text{true}}}}{e^{z_{\text{true}}} + e^{z_{\text{false}}}}
\]

其中 \(z_{\text{true}}\)、\(z_{\text{false}}\) 是模型给这两个词打的原始分数（logits）。

直觉：模型在答「做完了吗？」——只在「是 / 否」两个选项上打分，像考判断题，不是写作文。

### 4.1 提示词结构（模型「考卷」长什么样）

大致顺序：

1. **System**：你是 G1 长程任务调度 agent，三个 skill 各自是什么；  
2. **User 多模态内容**：按时间从早到晚，每个时刻标 `[2 秒前]` / `[1 秒前]` / `[当前时刻]`，下面依次是 ego 图、head 图、以及「本体:□□」（两个占位符）；  
3. **题干文字**：当前 skill 名称、描述、完成标准、请只输出 JSON；  
4. **（训练时）标准答案整句**；或 **（推理时）只接到 `{"done":`**。

同一套 `common.build_messages` / `user_text` 保证：训练、离线评估、真机节点看到的题干格式一致。  
格式不一致是微调常见翻车点——训的时候一种说法，跑的时候另一种说法，模型会对不上。

## 5. 每次判断，模型「看到」什么

每次决策固定看 **3 个时刻**：约 2 秒前、1 秒前、当前。  
每个时刻给：

1. **两张图**：ego（胸前）+ head（头部），缩到约 384×288；  
2. **一截本体向量**（154 维），再编成 2 个「软 token」塞进文字里的占位符。

所以一次决策大约是：\(3 \times 2 = 6\) 张图 + \(3 \times 2 = 6\) 个本体 soft token + 一段中文说明。

为什么要历史，而不是只看当前帧？

- 「刚停下」和「一直站着」在单帧上可能很像，但 2 秒轨迹不同；  
- skill2 要看到「放过玩偶后手臂收回」的过程；  
- skill3 要看到转向在积累，而不是某一瞬间的噪声。

### 5.1 本体向量包含什么

| 字段 | 维数 | 人话 |
|------|------|------|
| `body_q` | 29 | 身体各关节角度 |
| `body_dq` | 29 | 关节角速度 |
| `left/right_hand_q` | 7+7 | 双手关节 |
| `token_state` | 64 | 当前运动相关的内部 token |
| `last_*_hand_action` | 7+7 | 最近发给手的指令 |
| `base_ang_vel` | 3 | 基座角速度 |
| 本技能开始以来偏航变化 | 1 | 转了多少（skill3 很关键） |

处理步骤：

1. 按字段拼成向量；  
2. 用训练集均值/方差标准化，并截断到约 ±5，避免极端值炸掉；  
3. 小 MLP：`154 → 512 → 512 → (2 × 词向量维数)`；  
4. LayerNorm 后再乘一个可学习缩放，让数值尺度贴近文字 embedding；  
5. 在 embedding 层用 hook：凡是占位符 `<|fim_pad|>` 的位置，换成上面算出的 soft token。

### 5.2 为什么必须有「图像 dropout」

只喂真实图像时，模型很容易**只看图、完全忽略关节**——因为画面信息够用，一个 epoch 就能把损失压很低。  
但真机上：

- 光照、桌面布置会变；  
- skill2「右手是否归位」、skill3「是否转够」在关节上更稳。

所以训练时对 skill2 / skill3 约 30% 样本：把所有图换成灰色，只留真实本体。  
逼模型学会：「就算看不见，也能从手臂是否放下、是否转够来判断完成」。

skill1「走到桌前」主要靠视觉（没有可靠里程计），不做图像 dropout。

另外还有约 5% 的「本体 dropout」：故意藏本体，防止真机 `g1_debug` 短暂丢包时模型完全失灵。

**互斥细节**：某条样本若已经做了 image dropout，就不再对本条做 proprio dropout——否则输入几乎全空，学不到东西。

## 6. 标签怎么来？（老师按键 → 每帧对错）

人按「下一个技能」时，往往已经比「真正完成」晚了零点几秒到一秒。  
因此不能把「按键那一帧」当成唯一正确答案，而是按时间窗打标签：

以某个技能段结束（切到下一技能 / 任务结束）为锚点：

```text
时间轴 →

  …… 未完成(0) …… | 模糊区(忽略) | 完成(1) | 按键/结束
                     ↑              ↑
                 再往前 1s        结束前 1s
                                 （skill3 结束前 1.5s）
```

更细一点（默认 `LabelConfig`）：

| 区间 | 标签 | 含义 |
|------|------|------|
| 结束前较长时间 | `0`（未完成） | 还在做，不该切 |
| 再靠近一点 | `-1`（忽略） | 完成瞬间模糊，不拿来训练 |
| 结束前 1.0 s（末技能 1.5 s） | `1`（完成） | 已经该切 / 该结束 |
| 切换后 0.5 s 内 | 再给上一技能标 `1` | 画面仍是「上一技能完成态」，多攒正样本 |

为什么要有「忽略带」？  
因为完成边界本身就糊：早 0.3 s 和晚 0.3 s 都说得通。硬标对错会给模型互相矛盾的监督，不如留空。

为什么切换后还标上一技能为完成？  
刚切走后的前半秒，画面/姿态往往仍是「上一技能刚完成」；把它们当作上一技能的正样本，能缓解「完成瞬间太少」的样本失衡。

网页标注（`web_viewer.py`）可以改「1→2 / 2→3 / 结束」时间；保存后写入 `agents/annotations/<session>.json`，建数据集时自动覆盖录制里的原始按键时间，**不改原始录像**。

## 7. 训练细节：把一次更新拆开看

底座是开源多模态模型 **Qwen3-VL-4B-Instruct**。

### 7.1 哪些参数会动

| 部分 | 是否训练 | 说明 |
|------|----------|------|
| 视觉塔（看图） | 冻住 | 保持通用视觉能力 |
| 语言模型主体 | **LoRA 微调** | 只在 `q/k/v/o` 与 MLP 的 `gate/up/down` 上挂适配器 |
| 本体编码器 MLP | **一起训** | 学会把 154 维状态写成模型能用的 token |

默认超参直觉（见 `train_lora.py`）：

| 项 | 默认 | 人话 |
|----|------|------|
| epochs | 3 | 整套数据扫约 3 遍 |
| LoRA r / alpha | 16 / 32 | 补丁容量；越大越能拟合、也越易过拟合 |
| lr（LoRA） | 1e-4 | 语言模型补丁的学习率 |
| lr（encoder） | 5e-4 | 本体头从零学，可以稍大 |
| batch × accum | 4 × 2 | 等效 batch≈8，省显存 |
| image-dropout | 0.3 | skill2/3 三成样本变灰图 |
| proprio-dropout | 0.05 | 偶尔藏本体 |
| neg-keep | 0.5 | 每个 epoch 只抽一半「未完成」帧 |
| pos-repeat | 3 | 「完成」帧重复三遍 |

### 7.2 一条训练样本如何构造

对 `samples.jsonl` 里标签为 0 或 1 的一行（`-1` 已丢弃）：

1. 取出该帧对应的 3 个历史帧索引（训练时可对非当前帧做 ±2 帧时间抖动）；  
2. 按相机读出图像；训练时同一相机的 3 帧做**同一套**颜色/裁剪增强（避免时间轴上光怪陆离地乱抖）；  
3. 按需 image dropout → 6 张灰图；  
4. 拼出完整文本 = 提示 + 标准答案 JSON + 结束符；  
5. Processor 把「文 + 图」编成 `input_ids`、`pixel_values` 等；  
6. 找到答案段起点，确认决策位上的 token 真的是预期的 ` true`/` false`（对不齐就直接报错，避免默默训歪）；  
7. `labels`：提示部分填 `-100`（不算损失），答案部分填真实 token id；  
8. 若启用本体：附上 `[T, 154]` 向量，并标记本条是否 proprio dropout。

### 7.3 一次前向与损失（训练逻辑的心脏）

```text
batch 进模型
  ├─（若有本体）normalize → 加噪声 → × present掩码 → MLP → 写入占位符
  └─ Transformer 前向
        ├─ 总 LM loss：答案段所有 token 的交叉熵（整句 JSON 都要会写）
        └─ 决策位额外 CE：只在 true/false 两个logit上，对准 0/1 标签
loss = lm_loss + λ * decision_loss
反向传播 → 裁剪梯度 → 优化器步进
```

为什么既有整句 LM loss，又有决策位加权？

- 整句损失：让格式稳定（`skill`、`next` 字段别乱写），也利用完整答案上下文；  
- 决策位损失：把火力集中在真正要用于触发的那一个比特上——这才是上真机用的信号。

推理时只用决策位上的 true/false 概率，与训练时额外监督的位置一致。

### 7.4 每个 epoch 如何抽样

未完成帧远多于完成帧。若原样扫全数据，模型会偷懒「永远说没做完」也能得到不错的平均损失。

因此每个 epoch：

- 正样本（label=1）复制 `pos_repeat` 次；  
- 负样本以概率 `neg_keep` 保留；  
- 再打乱。

这是最朴素的类别再平衡，对小示范集特别重要。

### 7.5 验证时看什么

每个 epoch 结束后，在留出 session 上算：

| 指标 | 含义 |
|------|------|
| AUC | 把所有帧的 \(P(\text{done})\) 排序后，完成帧是否整体排在未完成帧前面（越近 1 越好） |
| TPR | 真正「该完成」的帧里，有多少被判 ≥0.5 |
| TNR | 真正「未完成」的帧里，有多少被判 <0.5 |
| balanced_acc | (TPR+TNR)/2，用作保存 best checkpoint 的主排序 |
| per_skill | 三个技能各自的上述指标 |
| proprio-only | **灰图**评估 skill2/3：专测本体有没有用上 |

保存策略：`balanced_acc` 最好的 epoch 写入 `adapter/`（含 LoRA、processor、`proprio_encoder.pt`、`agent_config.json`）。

注意：验证集上的帧级 AUC 高，**不等于**回放切换时刻一定准——后者还取决于阈值、连击、dwell、门禁。所以必须再跑 `eval_offline.py`。

### 7.6 两阶段训练习惯

1. **留出验证**：例如 6 条训、2 条验，调参、确认 proprio-only 正常；  
2. **全数据终训**：`--val-sessions none`，用全部示范榨干数据，给真机用。

数据很少时（例如总共 8 条），终训几乎必然「记住房间布置」；要用 dry-run、更多示范、失败/纠正样本来迭代泛化。

## 8. 离线评估：怎么判断训好了

`eval_offline.py` 用和真机**同一套触发逻辑**，在录像上假装实时跑：

1. 按时间滑动（默认 2 Hz），每次算 \(P(\text{done})\)；  
2. 还要过「最短运行时间」和「本体门禁」；  
3. 连续若干次都够高，才记一次「想切换」；  
4. 和人按键时刻比：误差 = 模型触发时刻 − 人按键时刻（负=偏早，正=偏晚）；漏切记为 MISS。

产出在 checkpoint 的 `eval/` 下（`*_pdone.png` 曲线、`eval_summary.json`）。  
也可在网页回放里叠加 \(P(\text{done})\) 曲线，肉眼看切换点是否合理。

常用诊断开关：

| 开关 | 测什么 |
|------|--------|
| 默认 | 完整链路（分数+门禁）接近真机 |
| `--no-gates` | 只看模型分数时机，排除门禁干扰 |
| `--blank-images` | 强制灰图，测本体贡献 |
| `--hide-proprio` | 本体当缺失，测纯视觉鲁棒性 |

常见结果解读：

| 现象 | 可能原因 | 可调方向 |
|------|----------|----------|
| 总是早切 | 阈值太敏感 / 门禁太松 | 提高 `threshold`、加大 `confirm`、加长 `min-dwell` |
| 总是晚切或漏切 | 阈值太保守 / 门禁太严 | 降低阈值、放松门禁、检查标注是否偏晚 |
| skill3 漏切 | 右转幅度门禁 + 末段很短 | 看 yaw 门禁；或补更多右转充分的示范 |
| 灰图评估全挂 | 本体没学到 | 确认训练用了 `--image-dropout`，并看 proprio-only 指标 |
| 验证 AUC 高但回放乱 | 帧级分类好，触发规则不匹配 | 调 TriggerConfig；或改标注窗口 |

## 9. 真机决策：模型说「完成」还不够

运行时约 **2 Hz** 问一次模型。即使 \(P(\text{done})\) 很高，也要同时满足：

| 条件 | 默认直觉 |
|------|----------|
| \(P(\text{done}) \ge 0.6\) 且连续 3 次 | 避免单帧误触发（约 1.5 秒确认） |
| 本技能已跑够最短时间 | skill1 ≥ 2s，skill2 ≥ 8s，skill3 ≥ 6s |
| skill2 本体门禁 | 右臂接近静息、右手指令接近松开 |
| skill3 本体门禁 | 本技能内偏航累计足够（约右转 ≥ 40°） |

门禁阈值来自示范统计（`meta.json → proprio_reference`）：看人切换时右臂偏离、结束时偏航大概落在什么范围，再留一点余量。

全部满足才发布 `skill:下一个`（与键盘完全同路径）。  
skill3 完成后默认只报任务完成；可选自动发 `i` 回站立。

**dry-run**：模型照常算分、打印「本来会切」，但**不真正发切换**。用于真机上先观察时机对不对，再关 dry-run 自动切。

人工随时可按 `1/2/3` 接管；agent 会跟随新技能，并定期与状态口对齐。

## 10. 它在整机系统里的位置

```text
相机 ──┬──► VLA 推理（真正动机器人）
       │         ▲
       └──► agent_node ── 发 "skill:2" / "skill:3" 等（原键盘口）
                 ▲
            本体 g1_debug（关节 + 门禁）
```

- Agent 替代原键盘终端，占用同一个 PUB 口；**不能和真键盘同时开**。  
- VLA 进程不用改：收到的切换命令和人手按键一模一样。  
- 显存上：VLA 约 12–15 GB，agent 约 9–11 GB（有上限），先起 VLA 再起 agent。

## 14. 记住这两张心智图

**原理（学什么）**

```text
人按键 = 老师
导出「画面+本体 → 完没完」考题
VLM 用 LoRA + 本体头做判断题
```

```text

  = 才真正发 skill:N
```

## 15. 第二代：技能边界裁判（现在推荐用这个）

前面 §0–§14 讲的是第一代：用 Qwen3-VL-4B 做判断题。第二代判断的还是同一件事——当前技能做完了没有，
但换了一个思路：**不再请一个会说话的大模型来当裁判，而是直接借用 VLA 自己已经有的东西，训一个很小的专用裁判。**

### 15.1 为什么要换

| 问题 | 4B 裁判 | 边界裁判 |
|------|---------|----------|
| 显存（和 VLA、对话 agent 抢同一张 32 GB 卡） | 8.6 GB | 约 1 GB |
| 每次判断耗时 | 79 ms，只能每秒判 2 次 | 约 10 ms，每秒判 10 次 |
| 训练数据 | 只有 8 条长程示范，容易背题 | 各 skill 的 VLA 遥操数据 1597 条（约 6.5 小时）+ 8 条示范 |
| 训练一次 | 29 min | 2 min |
| 和对话 agent 的关系 | 同一类大模型，容易想把两件事塞一起 | 完全分开：对话 agent 管「人想干什么」，边界裁判只管「做完没」 |

### 15.2 它借用了 VLA 的哪些东西

1. **同一双眼睛**：VLA 的共享 backbone 里有一个视觉塔，训练 VLA 时是冻结的，三个 skill 的权重一模一样。
   边界裁判直接从 VLA 的 checkpoint 把这套视觉塔加载过来，看画面的方式和 VLA 完全相同。
   每张图被压缩成 12 个「视觉 token」（3×4 的格子，每格一个向量）。
2. **同一份身体感觉**：VLA 用的 43 维关节状态（腿、腰、双臂、双手）和 64 维 SONIC motion token，
   真机 `g1_debug` 里本来就有，训练数据里也有，三处完全对齐。
3. **每个 skill 的「身体分布说明书」**：每个 skill 的 VLA checkpoint 都带一个 `statistics.json`，
   记录训练这个 skill 时关节和 token 的常见范围（q01 / q99 分位数）。VLA 用它做归一化，裁判也拿来用（见 15.4）。

### 15.3 老师从哪来：遥操录制的起止就是天然标签

每个 skill 的 VLA 训练数据是用 Pico 遥操一条一条录的，每条只录一个 skill：**开始录 = 这个 skill 开始，停止录 = 这个 skill 做完**。
所以不用人工标注，每条录制的结尾天然就是「完成」样本。统计（`analyze_vla_episodes.py`）也证实了这一点：

- skill1 和 skill3 停止录制前，机器人静止的时间中位数只有 0.1 s，说明一做完就停了录制；
- skill2 结尾多站了约 0.9 s，所以完成时刻取「最后一次在动的那一帧」，而不是死板地取最后一帧。

长程示范（VLA 自己在跑，人看着快结束时按键切）当作第二位老师，用**同一个定义**：
技能开始到人按键之间，机器人最后一次在动的那一帧。人按键只用来告诉我们「哪一次停下才是真正做完」
（VLA 中途也可能停顿），准确时刻由动作数据给出。示范里人按键时机器人平均已经停了 0.18 s（0.02–0.40 s）。

这个定义只看当前技能自己的动作，和后面接哪个技能无关。所以一条 1→2→3 的示范，其实是三份独立的样本：
「1 怎么结束」「2 怎么结束」「3 怎么结束」，以后顺序换成 1→3→2 也照样能用。

每一帧的标签：

```text
时间 →    ……未完成(0)…… | 忽略 0.5 s | 完成(1) ……
                                      ↑
                                 完成时刻 t_c
另外每一帧还有一个数字标签：还差几秒完成 τ = max(0, t_c − t)
```

### 15.4 「归一化」和「技能指纹」是什么意思

- **归一化**：身体状态按「当前 skill」的说明书归一化，和 VLA 自己处理输入的方式一样。
  同一个关节角，在「走路」和「抓玩偶」的说明书里意义不同，归一化后裁判看到的是「在这个 skill 里算不算常见」。
- **技能指纹**：告诉裁判「现在是哪个 skill」时，不用编号 1/2/3，而是把当前 skill 的说明书（q01/q99）直接喂进去。
  好处是以后加第 4、第 5 个 skill 时，只要有它的 VLA checkpoint 统计，网络结构不用改。
- **为什么不告诉它下一个 skill**：早期版本还按「下一个 skill」的说明书再归一化一遍，想让裁判看出「已经站在下一个 skill 的起点上」。
  但这样裁判学到的是「1 后面接 2」这种固定搭配，顺序一换（比如 1→3）输入就是它没见过的组合。
  现在顺序交给上层决定，裁判只回答「当前这个做完没有」。

### 15.5 网络长什么样

```text
最近 2 s 的身体（10 Hz，21 步）──► 每步一个 token ─┐
当前 skill 的指纹 ────────────────► 1 个上下文 token ├─ 4 层 Transformer（身体 token 当「提问者」，
CLS ─────────────────────────────────────────────┘   通过交叉注意力去「看」视觉 token）
2 s / 1 s / 0.5 s 前和当前的 ego、head 画面 ──► 4×2×12 = 96 个视觉 token
                         ▼
          P(完成)   +   还差几秒完成 τ̂
```

一共 500 万参数，是 4B 的约千分之一。训练时还会随机遮住画面（15%）或身体（10%），
所以任一路信号断了，另一路还能撑住（实测只给身体或只给画面，留出的 6 次切换都能切出来，只给画面时平均晚约 0.2 s）。

### 15.6 剩余时间 τ̂ 和提前量

二分类只能告诉你「已经做完了」，τ̂ 还能告诉你「还差 0.4 s 做完」。

只看 P(done) 会偏慢：机器人停下以后，裁判要「看到」一段静止才确信，再加连续 3 次确认，
24 次切换平均比机器人停下晚 0.33 s，比人还慢，skill1 还漏了 2 次。
所以默认 `--lead-s 0.3`：τ̂ ≤ 0.3 s 也算命中。实测平均正好在机器人停下那一刻切（+0.04 s），比人按键平均快 0.15 s，没有漏切。

代价是偶尔会提前切。C4 现在切技能会 hard restart（暂停、清动作、回 PLANNER），提前切会截掉上一个 skill 最后一点动作：
skill3 最多少转约 6.5°，skill1 偶尔最后半步没踩完。数字见 [skill_agent_auto_switch.md](skill_agent_auto_switch.md) §零「实测」。
提前量是运行时参数，调大调小都不用重训。等 C4 改成在动作块边界直接换 head、不回 PLANNER，就不会再截动作了。

### 15.7 实验里学到的三件事

1. **只用遥操数据不够，但很接近**：一条长程示范都不用，裁判对「哪一帧更接近完成」排得很准（AUC 0.92–0.995），
   但在 VLA 自主执行时偏保守，skill3 会漏切。原因是 VLA 自己做和人遥操做，动作节奏不一样。
   **少量长程示范的价值就是这层校准**——这也回答了「示范要录多少」：遥操数据管「懂动作」，示范管「懂 VLA 真机的节奏」。
2. **标签定义比模型大小更影响时机**：一开始把「完成」标签往前多标了 0.5 s，4B 因为判断慢，刚好把这 0.5 s 抵消了；
   新裁判每秒判 10 次，提前量就暴露出来，整体早切约 1 s。
3. **「完成」要对准机器人真正停下的时刻，「要多快」交给运行时参数**：后来用过「人按键 − 0.5 s」当完成时刻，
   以为人要 0.5 s 才反应过来；实际示范里人只晚了 0.02–0.40 s，标签就比机器人停下早，模型平均早切约 0.3 s。
   现在标签 = 机器人停下那一帧，想切得快一点就用 `--lead-s` 调，不用改标签重训。
4. **要用身体状态核对「早切」截掉了多少**：比人按键早不一定是坏事，关键看触发那一刻还剩多少动作。
   评估会算出每次提前切时剩下的转角和关节变化（见 auto_switch §零），用来决定提前量能开多大。
5. **回放评估要模拟「没人按键」**：录像里人按键之后已经是下一个 skill 的画面（最后一个 skill 录制直接结束），
   拿它判断上一个 skill 会造成假的漏切。评估改成按键后让机器人停在按键那一刻的姿态。

### 15.8 以后 skill 变多怎么办

1. 新 skill 照常遥操录 VLA 训练数据、训 VLA；
2. 在 `skill_registry.json` 里加一项：prompt、VLA checkpoint、遥操数据目录；
3. 录几段新 skill 由 VLA 自主执行到结束的示范（人按键切）。不用和每个前后技能组合着录，
   只执行这一个 skill 的 session 也能用；
4. 重跑 `build_boundary_dataset.py → train_boundary.py → eval_boundary.py`。

任务顺序由上层给：现在是 `agent_node.py --task-order 1 3 2` 或运行中输入 `o 1 3 2`，以后由语音对话 agent 按人的意图下发。
「哪个 skill 后面能接哪个」由上层自己保证（VLA 能否从上一个 skill 的结束姿态接上，需要在真机上验收）。
边界裁判只负责回答一件事：**当前这个 skill 做完了没有、还差几秒。**
